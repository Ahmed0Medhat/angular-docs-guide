## When to use
- Adding `@angular/localize` and marking template text, attributes and TypeScript strings for translation (`i18n`, `i18n-*`, `$localize`).
- Handling plurals, gender/select alternates and nested ICU expressions so each locale can phrase them correctly.
- Extracting a source message file (XLIFF, XMB, JSON, ARB) and producing per-locale translation files.
- Building one variant of the app per locale with `localize` / `ng build --localize`, or serving a single locale in development.
- Formatting dates, currency, decimals and percentages according to `LOCALE_ID`, or forcing a specific locale on a pipe.
- Deploying several locale builds behind Nginx/Apache, SSR, or as a prerendered static site.
- See also: data transformation pipes and text interpolation → references/guide/templates.md
- See also: building, serving and deploying apps with the CLI → references/tools/cli.md
- See also: server rendering, `outputMode` and static generation → references/guide/ssr.md

## Rules
- MUST install the package with `ng add @angular/localize` before building a localized app; it updates `package.json`, adds `types: ["@angular/localize"]` to the tsconfig files and puts `/// <reference types="@angular/localize" />` at the top of `main.ts`.
- PREFER `--use-at-runtime` on `ng add` only when `$localize` must work at runtime; it moves the package into `dependencies` instead of the default `devDependencies`.
- MUST decide the target languages and locales up front; locales sharing a language still differ in grammar, punctuation, currency, number and date formats.
- MUST use Unicode/CLDR locale IDs based on BCP 47 tags: `{language_id}-{locale_extension}` (for example `en-CA`, `en-US`, `fr-CA`, `fr-FR`).
- MUST set `i18n.sourceLocale` in `angular.json` when the source language is not `en-US` (the default).
- PREFER injecting `LOCALE_ID` inside components and services to read the active locale; outside an injection context read `$localize.locale` instead.
- MUST put the `i18n` attribute on every element whose fixed text should be translated.
- PREFER wrapping loose text in `<ng-container i18n>` when you do not want an extra DOM element; it renders as an HTML comment.
- PREFER naming interpolation placeholders for translators: `{{ expr //i18n(ph="name") }}` in templates, `${expr}:name:` in `$localize`.
- MUST mark translatable attributes with `i18n-{attribute_name}` (works on any attribute of any element), for example `i18n-title`.
- MUST mark strings in component code with the `$localize` tagged template; metadata goes between colons before the text: `` $localize`:{meta}:text` ``.
- PREFER adding a description and, when the same text must be translated consistently across the app, a meaning: `{meaning}|{description}@@{custom_id}`.
- MUST use the `plural` ICU clause for counts instead of word-for-word text, and always include an `other` case as the fallback.
- MUST use the `select` ICU clause for string-valued alternates (for example gender), with an `other` fallback.
- MUST create each translation file by copying the extracted source file, renaming it `messages.{locale}.xlf`, and placing it in `src/locale`.
- MUST translate by duplicating `<source>` into a `<target>` element within the same `<trans-unit>`.
- NEVER change the `id` of a translation unit; Angular derives it from the text and the meaning.
- MUST keep `<x id="ICU">` and `<x id="INTERPOLATION">` placeholders in translations; moving them is allowed, removing them is not.
- PREFER adding or removing plural cases per target language according to the CLDR plural rules.
- MUST declare locales under the project's `i18n` option (`sourceLocale`, `locales`) in `angular.json` and enable `"localize"` to produce variants.
- MUST keep AOT compilation enabled to localize templates; if you changed it, set `"aot": true`.
- MUST use `ng serve` with only one locale; for development against a locale set `"localize": ["fr"]` in a dedicated configuration.
- PREFER defining `"localize"` in shared options so every configuration inherits it, and override it per configuration where needed.
- PREFER configuration composition for a production build of one locale: `ng build --configuration=production,fr`.
- PREFER `"i18nMissingTranslation": "error"` in the build target `options` when missing translations must fail the build.
- MUST define custom IDs (`@@id`) that are unique across the app.
- PREFER generated IDs for most projects; use custom IDs only when a translation system requires a specific ID syntax or you want IDs to carry metadata (library, component, area).
- PREFER importing global locale variants from `@angular/common/locales/global/<locale>` in `main.ts` (or in `app.module` for NgModule apps) when you need that locale's data loaded globally.
- MUST configure your host to redirect by `Accept-Language` and serve per-locale not-found pages when using `outputMode: "static"`.

## API cheat-sheet
| API | Purpose | Notes / version tag |
| --- | --- | --- |
| `ng add @angular/localize` | Installs localize support | Options: `--project <string>`; `--use-at-runtime` (boolean, default `false`) |
| `i18n` attribute | Marks element text for translation | Value is optional metadata `meaning\|description@@id` |
| `i18n-{attr}` | Marks an attribute value for translation | Same metadata syntax as `i18n` |
| `//i18n(ph="name")` | Names an interpolation placeholder in a template | Placed inside `{{ }}` after the expression |
| `$localize` | Tagged template for translatable strings in code | Import from `@angular/localize/init`; `${v}:name:` names a placeholder |
| `$localize.locale` | Active locale string set by each localized build | Read by the default `LOCALE_ID` factory; does not reflect a custom `LOCALE_ID` provider |
| `LOCALE_ID` | Token holding the active locale | Used by locale-aware pipes; `en-US` data ships by default |
| `DatePipe` / `CurrencyPipe` / `DecimalPipe` / `PercentPipe` | Locale-aware formatting of dates, currency, decimals, percentages | Last pipe argument `locale` overrides `LOCALE_ID` for that call |
| `{prop, plural, ...}` | ICU plural expression | Categories `zero`, `one`, `two`, `few`, `many`, `other`; exact matches `=0`, `=1`, `=2` |
| `{prop, select, ...}` | ICU select expression on string values | `other` used when nothing matches; can be nested inside `plural` |
| `ng extract-i18n` | Extracts marked text to `messages.xlf` (XLIFF 1.2) in the project root | `--format`, `--out-file`, `--output-path` |
| `--format` values | Output format | `xlf` (XLIFF 1.2, `.xlf`), `xlf2` (XLIFF 2, `.xlf`), `xmb` (`.xmb` source, `.xtb` translations), `json` (`.json`), `arb` (`.arb`) |
| `i18n.sourceLocale` (angular.json) | Locale of the source code | Default `en-US`; string or object `{ code, baseHref, subPath }` |
| `i18n.locales` (angular.json) | Map of locale ID to translation file | Value is a path or object `{ translation, baseHref, subPath }` |
| `subPath` | URL segment / output folder for a locale | Defaults to the locale ID; `""` serves that locale from the root |
| `"localize"` (build option) | Which locale variants to build | `true` = all defined locales; array = subset; `false` = none |
| `ng build --localize` | Builds every locale defined in the config | Equivalent to `"localize": true` |
| `i18nMissingTranslation` (build option) | Severity for missing translations | `error` (build fails), `warning` (default message), `ignore` |
| `@angular/common/locales/global/<id>` | Global variant of a locale's data | Side-effect import, e.g. `.../global/fr` |
| `outputMode: "server"` / `"static"` | SSR redirect vs. per-locale prerender | `server` redirects on `Accept-Language` automatically; `static` prerenders `RenderMode.Prerender` routes per locale |

### i18n metadata
| Part | Syntax | Effect |
| --- | --- | --- |
| Meaning | `meaning\|` prefix | Part of the generated ID; same text with different meanings yields separate units |
| Description | plain text | Context for translators; does not affect the ID |
| Custom ID | `@@id` suffix | Replaces the generated ID; stays stable when text changes |

## Patterns

### Install
```shell
ng add @angular/localize
```

### Set the source locale
```json
{
  "projects": {
    "my-app": {
      "i18n": { "sourceLocale": "ca" }
    }
  }
}
```

### Read the locale outside DI
```ts
// file must contain an import or export; drop the declare if @angular/localize types are present
declare const $localize: {locale?: string};

export const activeLocale =
  (typeof $localize !== 'undefined' && $localize.locale) || 'en-US';
```

### Locale-aware pipes
```html
<p>{{ now | date }}</p>
<p>{{ total | currency: 'USD' : 'symbol' : '1.2-2' : 'en-US' }}</p>
```

### Marking template text and attributes
```html
<h1 i18n="site header|Welcome heading on the landing page@@welcomeTitle">Welcome!</h1>
<ng-container i18n>Text without a wrapper element</ng-container>
<p i18n>Hi, {{ user.name //i18n(ph="userName") }}!</p>
<img [src]="logoUrl" i18n-title title="Company logo" alt="Company logo" />
```

### Marking strings in code
```ts
import {Component, computed, signal} from '@angular/core';
import {$localize} from '@angular/localize/init';

@Component({selector: 'app-panel', templateUrl: './panel.html'})
export class Panel {
  readonly open = signal(false);
  readonly label = computed(() =>
    this.open()
      ? $localize`:Panel toggle|Toggle button label:Collapse`
      : $localize`:Panel toggle|Toggle button label:Expand`,
  );
  greet(user: string) {
    return $localize`:@@greeting:Hello, ${user}:userName:!`;
  }
}
```
```html
<button type="button" (click)="open.update((v) => !v)">Toggle</button>
<div i18n [attr.aria-label]="label()">{{ open() }}</div>
```

### Plural, select and nested ICU
```html
<span i18n>Saved {count, plural, =0 {never} =1 {once} other {{{ count }} times}}</span>

<span i18n>The reviewer is {role, select, admin {an admin} editor {an editor} other {a guest}}</span>

<span i18n>Saved:
  {count, plural,
    =0 {never}
    =1 {once}
    other {{{ count }} times by {role, select, admin {an admin} editor {an editor} other {a guest}}}
  }
</span>
```

### Extraction commands
```shell
ng extract-i18n
ng extract-i18n --output-path src/locale
ng extract-i18n --format=xlf2        # also: xlf, xmb, json, arb
ng extract-i18n --out-file source.xlf
```

### Translating a unit (XLIFF 1.2)
```xml
<trans-unit id="welcomeTitle" datatype="html">
  <source>Welcome!</source>
  <target>Bienvenue !</target>
  <note priority="1" from="description">Welcome heading on the landing page</note>
  <note priority="1" from="meaning">site header</note>
</trans-unit>
```
- The custom ID appears in the file without its `@@` prefix.
- A `select` (or nested) expression is extracted as two units: the outer text holding `<x id="ICU" .../>`, and the ICU expression itself (`{VAR_SELECT, select, ...}` / `{VAR_PLURAL, plural, ...}`). Translate both.
- Interpolations inside ICU cases appear as `<x id="INTERPOLATION" equiv-text="{{count}}"/>`.

### angular.json: locales, variants, single-locale config, missing translations
```json
{
  "projects": {
    "my-app": {
      "i18n": {
        "sourceLocale": "en-US",
        "locales": {
          "fr": { "translation": "src/locale/messages.fr.xlf", "subPath": "" }
        }
      },
      "architect": {
        "build": {
          "options": {
            "localize": true,
            "i18nMissingTranslation": "error"
          },
          "configurations": {
            "development": { "localize": false },
            "fr": { "localize": ["fr"] }
          }
        },
        "serve": {
          "configurations": {
            "fr": { "buildTarget": "my-app:build:development,fr" }
          }
        }
      }
    }
  }
}
```
```shell
ng build --localize
ng serve --configuration=fr
ng build --configuration=production,fr
```

### Serve the source locale from `/` (static prerender)
```json
{
  "i18n": {
    "sourceLocale": { "code": "en", "subPath": "" },
    "locales": {
      "tr": "src/locale/messages.tr.xlf",
      "es": "src/locale/messages.es.xlf"
    }
  }
}
```
Output: `browser/index.html` (`lang="en"`, `<base href="/">`), `browser/tr/...` (`lang="tr"`, `<base href="/tr/">`), `browser/es/...` (`lang="es"`, `<base href="/es/">`); each locale folder has its own prerendered HTML, bundles and copy of `public/`.

### Global locale data
```ts
import '@angular/common/locales/global/fr';
import {bootstrapApplication} from '@angular/platform-browser';
import {App} from './app/app';

bootstrapApplication(App);
```

### Server redirect by Accept-Language (Nginx sketch)
```nginx
map $http_accept_language $accept_language {
  ~*^de de;
  ~*^fr fr;
  ~*^en "";
}
server {
  root /www/data;
  if ($accept_language ~ "^$") { set $accept_language "fr"; }
  rewrite ^/$ /$accept_language permanent;
  location ~ ^/(fr|de|$) {
    if ($accept_language = "") { try_files $uri /index.html?$args; }
    try_files $uri /$1/index.html?$args;
  }
}
```
- Apache equivalent: `RewriteCond %{HTTP:Accept-Language} ^de [NC]` + `RewriteRule ^$ /de/ [R]` per language, a catch-all for unsupported languages, and a fallback rule serving `<locale>/index.html` when the requested file or directory does not exist.

## Pitfalls
- Building a localized app (for example with `i18n` attributes) without `@angular/localize` installed makes the CLI raise an error that lists how to enable i18n.
- `$localize.locale` ignores an app-provided `LOCALE_ID`; it only reflects what the localized build set.
- The default `en-US` `plural()` function returns only `one` or `other`, so `few` never matches; `es` is similarly simple. Many locales lack some categories.
- Two messages with the same text and meaning but different descriptions are extracted once and share one translation everywhere; different meanings produce different IDs and translations.
- Changing source text or meaning regenerates the generated ID, so the translation must be updated; with a custom ID the ID stays, but the translation can silently go stale.
- Reusing one custom ID for different texts: only the first is extracted and its translation replaces both (e.g. both render `Bonjour`).
- Removing an `<x id="ICU">` placeholder from a translation drops the whole ICU expression from the translated app.
- `ng serve` with `"localize": true` or more than one locale logs a warning and turns localization off.
- A missing translation does not fail the build by default; it prints `Missing translation for message "..."` unless `i18nMissingTranslation` is `error`.
- The `xmb` format writes `.xmb` source files but expects `.xtb` translation files.
- Without an empty `subPath` on the object-form `sourceLocale`, the source locale is placed in its own `/en/`-style folder instead of the root.
- Static output (`outputMode: "static"`) never redirects on `Accept-Language` and no server picks the language; your host must handle redirects and 404s. The sample Nginx/Apache configs assume every locale, default included, has its own subfolder, so adapt them to redirect `/` only for the non-root locales.
- The `**` wildcard route is not prerendered; declare a concrete route like `404`, prerender it, and map missing URLs per locale (`error_page` in Nginx, `ErrorDocument` in Apache), e.g. `/404/index.html` and `/tr/404/index.html`.
- With `outputMode: "server"` SSR, Angular already redirects by `Accept-Language`; no manual server config is needed.
- Each localized variant gets `lang` on `<html>` set to its locale and its base HREF adjusted (configured `baseHref` plus the locale's `subPath`).
- `i18n` attributes compile into `$localize` calls and translation is applied after compilation, so you compile once and translate per locale without recompiling the whole project.
